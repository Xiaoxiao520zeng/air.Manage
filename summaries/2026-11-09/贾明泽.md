## 今日完成

1. **复习 YOLOv8 检测原理并整理手写笔记**：输入 `3×640×640` → 三层输出 `80×80` / `40×40` / `20×20`，对应数据点 `6400` / `1600` / `400`；特征图越大、感受野越小、负责的框越小（分别管小 / 中 / 大目标）。每个预测框输出 `(x1, y1, x2, y2, C, S)`：4 个位置 + 类别 C + 置信度 S。NMS 三步：按置信度排序 → 保留最高分框并按 IoU 抑制冗余 → 重复直到处理完。
2. **把笔记和项目实际结构逐条核对，纠正一处认知**：标准 YOLOv8 的主干（C2f + SPPF）和颈部（PAN-FPN）都是卷积，**不含 Transformer**。项目里 v2-T 曾把 Neck 换成 C3TR 试过，mAP50 反而从 0.800 掉到 0.795、显存 +86%，已经回退——所以「YOLOv8 + Transformer」是实验项，不是默认结构。
3. **梳理绝缘子检测项目现状，产出速查卡片**：环境（独立 .venv，torch 2.15.0+cu132 / ultralytics 8.4.202 / depthai 3.12.0）、5 个双击入口、v1~v5 版本成绩（现役 v4，三类 mAP50 = 0.835）、关键路径、已知问题和下次优先级，归档成本地笔记，全文附在文末。

## 遇到的问题

- **小目标仍是最大短板**：640 输入下最细特征图 20×20，一格对应原图 32 像素，小于约 10 像素的目标基本看不见。全图直接推理时整串里的破损被压缩到 13 像素，实测 0 个检出；改为两级识别（先找整串，裁出来放大到 40+ 像素再复查）后检出 5 个。
- **端侧帧率受限**：相机走 USB2（设备名 `1.x`）预览只有 12~15 fps；RVC2 芯片 640 输入约 13 fps、960 只 4~5 fps，属硬件上限。
- **域外误检**：房间里的人头、椅子曾被框成绝缘子。加 90 张背景负样本后误检降到 0/30，但整体 mAP 从 0.835 掉到 0.805，只能作备份版本。
- **训练数据缺陷**：真实场景（尤其国内瓷件、复合伞裙）的破损样本缺失；CPLID 的 248 张缺陷是人工合成图，导致早期 v1 出现 0.991 的虚高分数。

## 明日计划

#### 环境坑

- 本机代理 `127.0.0.1:7897`：ultralytics 自动下载数据集会走代理被掐断 → 先 `$env:NO_PROXY="*"`
- Windows 多进程读数据会卡死 → 脚本里 `workers=0`
- 8 GB 显存：`yolov8n` + `batch 8~16` + `imgsz 640` 最稳
- `device=0` 是显卡，`device="cpu"` 慢几十倍
- 中文乱码：bat 里已 `set PYTHONIOENCODING=gbk`；手动跑 python 时设 `utf-8`
- DSH 沙箱里跑训练会报「命名管道 Permission denied」→ 要在用户自己的 PowerShell 里跑
- `.bat` 里设了 `LOCALAPPDATA=%~dp0.appdata`，避免往系统目录写缓存
