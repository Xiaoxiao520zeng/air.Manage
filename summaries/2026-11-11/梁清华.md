## 附：云台联调与参数核对笔记

### 一、联调按层排查，不要一上来就调参

| 层次 | 要确认的事 | 判断方法 |
| --- | --- | --- |
| 设备节点 | 节点在不在、名字会不会变 | `ls /dev/ttyUSB*`，有 udev 规则时看符号链接 |
| 串口参数 | 波特率、数据位、校验位、停止位 | 与板子默认值逐项核对，别只看上位机默认 |
| 协议帧 | 帧头、长度、校验、指令字节 | 抓原始字节看返回帧是否合法，而不是只看界面报错 |
| 设备状态 | 板子是否处于可配置模式 | 部分板子需要先解锁或切到 config 状态才接受写入 |
| 机械与参数 | 极对数、IMU 方向、限位、电流限幅 | 单轴低速点动，看转向与补偿方向是否一致 |

只有前四层都通了，「调 PID」才有意义。前四层没通就去调参，等于在错误的前提上做优化。

### 二、上电测试的顺序（不要跳步）

```text
1. 空载、低速、单轴     —— 只看能不能转、转向对不对
2. 三轴联动、空载       —— 看有没有互相干扰、异常发热
3. 带相机负载、小角度   —— 看带载后是否堵转、是否抖动变大
4. 进入 PID 增稳调参    —— 前 3 步都稳定之后
```

任何一步出现异响、电机发烫、持续抖动，立刻断电。带浆或带载状态下的失控比调参浪费时间严重得多。

### 三、必须与实物逐项核对的参数

1. **电机极对数**：配错会让换相节奏和实际转子位置错位，表现为转不准、发热、低速顿挫。
2. **IMU 安装方向**：板载还是外置、正装还是反装。方向反了补偿就变成「反向助推」，越稳越抖。
3. **每轴限位角度**：机械结构能到哪，参数就限到哪，否则电机顶着结构件堵转烧线圈。
4. **电流限幅**：保护电机和驱动级，先给小值，确认动作正常再逐步放宽。
5. **波特率与协议版本**：上位机与固件必须匹配，这是「能连上但写不进参数」最常见的原因。

### 四、写在最后的经验

昨天和今天连着踩的两个坑其实是同一类问题：**看起来像硬件或算法的问题，根因都在更下面一层**。昨天是 Linux 权限（不在 `dialout` 组），今天是串口参数与占用。所以排查顺序永远是从下往上：节点 → 权限 → 占用 → 参数 → 协议 → 才轮到算法。
