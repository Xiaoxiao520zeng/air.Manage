# 2026-11-19 日总结 · 贾明泽

## 今日完成

1. **把树莓派 5 的网络问题定位清楚了**。之前一直以为是在树莓派上装了虚拟机，后来确认其实是**官方 Ubuntu 镜像烧进 SD 卡、直接裸机跑**，所以那些「虚拟机网络模式」的思路全是白折腾。
   - 裸机 Ubuntu Server 的网络由 **netplan + systemd-networkd** 管，根本没有 NetworkManager，所以 `systemctl restart NetworkManager` 会报 `Unit NetworkManager.service not found`。
   - 网卡 `eth0`、`wlan0` 一开始都是 DOWN，`eth0` 还带 NO-CARRIER（链路没接通）。
   - 实际生效的解法：`sudo netplan set ethernets.eth0.dhcp4=true` 然后 `sudo netplan apply`，`eth0` 就拿到了 IP。
2. **搞清树莓派 5 的供电要求**：满载约 **5V/5A（25W）**，官方电源是 5.1V/5A（27W）。电源不够时系统会打印 `This power supply is not capable of supplying 5A`，并且限制 USB 外设的电流。
   - 手上的 **Matek BEC12S-PRO** 参数符合：输入 9–55V（3S–12S），输出默认 **5.2V**，持续 5A、峰值 9A。
   - 手上的 **GTech 6S 1450mAh 75C** 电池：22.2V 标称、满电 25.2V，落在 BEC 的输入范围内，可以用。
3. **理清了「电池 → 降压模块 → 树莓派」的接线原则**：
   - 输入端：电池正极 → `IN+`，负极 → `IN-`，**这块 BEC 没有防反接保护，接反会直接烧**。
   - 输出端优先走 **USB-C**（能用到树莓派板载的电源管理保护）；**不要**把 5.2V 直接怼到 40Pin 的 5V 引脚上；更不要 USB-C 和 GPIO 同时供电。
   - 用 USB-C 线接时，如果只焊 VBUS/GND，树莓派可能识别不到 5A 电源，标准做法是在 **CC1 与 GND 之间加 5.1kΩ 电阻**。
   - 接线前必须先用万用表确认 `OUT+ / OUT-` 在 **5.1～5.2V**。
4. **搞明白了万用表测电流的正确姿势和风险**（DT-9205A+）：
   - 测电压是并联，测电流必须**串联**（把电路断开，让电流从表里穿过）。
   - 红表笔插 **20A** 孔、黑表笔插 **COM**、旋钮打到直流 10A 档；这个孔**没有保险丝、限时 10 秒**，表笔尖绝对不能互碰。
   - 测完立刻把红表笔插回 `VΩ` 孔、旋钮回 20V 档，否则下次测电压会直接短路。
5. **补充了电池常识**：`S` 是 Series（串联，升压），`P` 是 Parallel（并联，增容）；单节锂电 3.7V，6S = 22.2V；75C × 1.45Ah ≈ 108A 只是「能放出这么多」的上限，负载需要多少才取多少，**不会因为电池放电能力强就把树莓派烧了**。

## 遇到的问题

- **方向一开始就跑偏了**：把「树莓派裸机 Ubuntu」当成「树莓派上的虚拟机」，查了半天 NAT/桥接，纯属浪费时间。教训是**先确认环境到底是什么**（虚拟化 or 裸机），再动手。
- **命令细节踩坑**：
  - `sudo ip link set eth0 up` 报 `Object "link" is unknown`，正确写法要带 `dev`：`ip link set dev eth0 up`；
  - `sudo dhclient -v eth0` 报 `command not found`，精简镜像没带 `isc-dhcp-client`，只能靠 netplan；
  - `dpkg -l | grep ...` 把字母 `l` 打成了数字 `1`，报 `unknown option -1`。
- **电源功率不足是真实警告**：用普通 5V/3A 充电头时系统会限流，装桌面这种大下载量的操作很容易卡死或掉电重启。
- **cloud-init 会覆盖网络配置**：`netplan set` 改完当时能用，树莓派 5 的 Ubuntu 镜像重启后可能被云初始化流程改回去，需要另写 `99-` 配置固定下来。
- **测电流对新手确实危险**：20A 孔无保险丝，一旦并联接法或者表笔相碰，6S 电池的短路电流足以把表笔线烧红。
- **桌面还没装上**：`dpkg -l | grep xubuntu-desktop` 没有任何输出，说明之前那次 `apt install` 因为没网直接失败了，得趁现在网络通着重装。

## 明日计划
